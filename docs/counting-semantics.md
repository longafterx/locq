# locq 统计语义契约

契约版本：`locq-counting-v1`。独立逐行期望位于 `internal/lexertest`，语言适用范围见
[测试矩阵](language-test-matrix.md)。外部工具的结果是差异调查线索，不是正确性定义。

## 物理行与分类

统计单位是物理行，不是语句、字符、AST 节点或嵌入语言片段。LF 分隔物理行；CRLF
与 LF 的分类相同。单独的 CR 不创建新行。空文件有 0 行；末尾 LF 不额外创建一行；
最后一行即使没有 LF，也计数，包括只包含空白的末行。

成功完整扫描的每个文件满足：`物理行数 = Code + Comment + Blank`。
每个物理行只属于一个类别，优先级如下：

1. 物理空白行算 Blank，包括注释、字符串、文档字符串内部的空白行。
   空白判断采用 Go 的 Unicode 空白语义，不把任意不可见字符当作空白。
2. 非空白行只要有注释以外的代码或普通字符串内容，就算 Code。
   代码与行尾注释、块注释结束后的代码，都只增加一行 Code。
3. 其余纯注释、符合该语言文档字符串规则的行算 Comment。

例如，以下六行的期望依次为 `CBMCBC`，合计 Code=3、Comment=1、Blank=2：

```go
package main

/* 注释开始
   注释结束 */ var a = 1

func main() {} // 行尾注释
```

`internal/lexertest/contracts.go` 的混合行用例约束该优先级；`Kinds` 中
`C` / `M` / `B` 分别表示 Code / Comment / Blank。Kinds 必须独立推导和评审，
禁止用当前扫描器的输出自动更新期望。

## 字符串与注释状态

- 字符串中的注释标记不启动注释；注释中的引号不启动字符串。
- 注释与引号的开头采用最长匹配。嵌套注释只对声明支持的规则生效。
- 多行字符串、转义、双写结束引号、原始字符串按各语言已声明的规则处理。
  Go 原始字符串、Java 文本块、C++ 动态 raw 分隔符和 Rust raw hash 数量有专项用例。
- Python 的模块、def/class 体首个独立字符串表达式算文档；注释、空行、shebang
  不消耗文档位置。赋值、后续字符串表达式、bytes/f-string 算代码。
  这是轻量词法/缩进规则，不是完整 Python 语法解析。
- 新引擎仅在物理第一行识别 shebang，算 Code；首行 UTF-8 BOM 不作为源码 token。
  BOM 不创建额外行。字符串/注释状态属于单个文件，不能继承到下一文件。

非法或不完整源码仍尽力分类，不要求语法解析成功。普通引号的换行恢复是语言规则，
并不统一：Go、C/C++、Java、JS/TS、Python 等在不允许跨行的普通引号后恢复；Rust
普通双引号、SQL 单引号和某些通用规则保留状态。SQL 规则不是所有方言的合集；
例如不能由单引号支持推断双引号、美元引用、方言专有字面量的行为。

## 历史兼容与明确缺口

50 种未迁移语言保留旧引擎。矩阵逐条列出原因，完整旧引擎对照测试继续运行；
新规则生成不会顺带开启这些语言。

- HTML、Markdown、Vue、Svelte、JSX、notebook 等保持现有整体分类，尚未提供通用
  script/style、代码围栏、单元格或宿主/嵌入语言分别统计。
- 历史 HTML、Svelte 全局识别 `//`，Vue 的旧标记不同。它们不是统一的 HTML/JS
  语法解释器；独立 legacy golden 明确固定这些不同的既有行为。
- Plain Text 的非空文本算 Code。tokei 将其算 Comment 是可解释的语义差异。
- 旧引擎的 BOM/shebang 顺序与 first-line 标记有历史差异。不能把新引擎的首物理行
  规则用于旧引擎；`TestEngineFirstLineSemantics` 固定两者区别。
- 动态 shell heredoc、完整 JavaScript regex/division 语法判定、Python 带括号文档
  字符串和 f-string 替换表达式等不在完整支持承诺内。

未声明支持的特性应记录为缺口，不能依靠跨工具一致率宣称完整语言支持。

## 执行、错误与聚合

计数、OnLine、Debug、整块读取、任意分片读取必须给出相同的逐行分类。
`OnLine.Number` 从 1 开始且严格递增；Text 是引擎归一化、裁剪后的文本，不保证
与原始字节相同。调查报告保留原文件字节和 SHA-256，不能把 Text 当作原文。

读取失败时结果可能不完整；非 EOF 错误伴随的未完成当前行不计入。已发送的事件
不回滚。上述行数守恒仅对成功完整扫描成立。目录扫描可能跳过不可读文件并输出
诊断，因此“返回 nil error”不能单独证明文件集合完整。

同一文件集合、规则和去重设置下，1/8 个 worker 的逐文件及聚合结果必须一致。
去重默认关闭；开启后按首次发现顺序保留相同字节内容的一个副本，不能按 worker
完成顺序选择。各文件计数之和必须等于对应语言计数，再等于总计。
